# RouterProvider

`RouterProvider` — компонент, который предоставляет объект [роутера](libraries/router) и дополнительные параметры для вашего React-приложения. Позволяет использовать [хуки библиотеки vk-mini-apps-router](libraries/router/reference#Hooks) во вложенных компонентах.

Используйте `RouterProvider` как компонент-обёртку для компонента вашего приложения.

## Пример

```TypeScript
import { AdaptivityProvider, AppRoot, ConfigProvider } from '@vkontakte/vkui';
import App from './App'; // Компонент вашего приложения
import { router } from './routes';
import { RouterProvider } from 'dist/index';

export const AppConfig = () => {
  return (
    <ConfigProvider>
      <AdaptivityProvider>
        <AppRoot>
          <RouterProvider router={router} notFound={<p>'Custom not found'</p>}>
            <App />
          </RouterProvider>
        </AppRoot>
      </AdaptivityProvider>
    </ConfigProvider>
  );
}
```

## Свойства

| Свойство | Тип | Описание |
| --- | --- | --- |
| `router`&#x0d;&#x0a;*обязательное* | [`Router`](libraries/router/reference/functions/createHashRouter#Результат) | Объект типа `Router`, созданный при помощи функции [`createHashRouter`](libraries/router/reference/functions/createHashRouter). |
| `throttled`&#x0d;&#x0a;*необязательное* | `boolean` | Включение задержки для навигации.&#x0d;&#x0a;&#x0d;&#x0a;Если значение `true`, то частота возникновения событий навигации ограничена параметром `interval`. Если в течение этого периода произойдёт несколько событий навигации, будет обработано только последнее. Такая функциональность помогает обеспечить работоспособность и плавность анимаций [VKUI](libraries/vkui).&#x0d;&#x0a;&#x0d;&#x0a;Если свойство установлено в `false`, то специальная обработка событий навигации не используется.&#x0d;&#x0a;&#x0d;&#x0a;Значение по умолчанию: `true`. |
| `interval`&#x0d;&#x0a;*необязательное* | `number` | Минимальная задержка между двумя последовательными навигациями в миллисекундах. Используется, когда `throttled: true`.&#x0d;&#x0a;&#x0d;&#x0a;Значение по умолчанию: `400`. |
| `useBridge`&#x0d;&#x0a;*необязательное* | `boolean` | Указывает, использует React-приложение библиотеку [VK Bridge](bridge/overview) или нет.&#x0d;&#x0a;&#x0d;&#x0a;Если React-приложение — это [мини-приложение](mini-apps/overview), которое запускается из десктопной или мобильной версии сайта ВКонтакте или из мобильного приложения ВКонтакте для Android или iOS, свойство должно быть `true`.&#x0d;&#x0a;&#x0d;&#x0a;В ином случае свойство должно быть `false`.&#x0d;&#x0a;&#x0d;&#x0a;Значение по умолчанию: `true`. |
| `notFound`&#x0d;&#x0a;*необязательное* | `JSX.Element` | React-компонент, который будет отображён при попытке перехода по несуществующему URL, то есть при возникновении ошибки `404 Not Found`.&#x0d;&#x0a;&#x0d;&#x0a;Атрибут игнорируется, если указан атрибут `notFoundRedirectPath` или определён маршрут со свойством `path: '*'`. Подробности — в разделе [Обработка ошибок](libraries/router/handling-errors). |
| `notFoundRedirectPath`&#x0d;&#x0a;*необязательное* | `string` | Адрес страницы в приложении, например `/persik/welcome-screen`, который будет открыт при попытке перехода по несуществующему URL, то есть при возникновении ошибки `404 Not Found`. Подробности — в разделе [Обработка ошибок](libraries/router/handling-errors). |
| `hierarchy`&#x0d;&#x0a;*необязательное* | [`RouteLeaf[]`](#Использование%20свойства%20hierarchy) | Древовидная структура адресов, которые будут добавлены в историю переходов, когда пользователь входит в приложение по ссылке, содержащей параметр `?inflate=true`. Используйте эту структуру, чтобы наполнить историю переходов для каждого маршрута в вашем приложении. Примеры работы с этим свойством даны [ниже](#Использование%20свойства%20hierarchy).&#x0d;&#x0a;&#x0d;&#x0a;Значение по умолчанию: `undefined`. |

Компонент `RouterProvider` также содержит стандартные свойства, которые используются в React-компонентах, например `children`, которое предоставляет доступ к вложенным JSX-элементам.  

## Использование свойства `hierarchy`

Используйте свойство `hierarchy`, чтобы вставить дополнительные пути в историю навигации. Роутер будет добавлять их каждый раз, когда пользователь переходит в приложение по ссылке с query-параметром `?inflate=true`. Давайте рассмотрим, зачем это может быть нужно.

Предположим, в вашем приложении есть главная страница, каталог товаров и карточка отдельного товара. При запуске приложения пользователь обычно проходит последовательно через главную страницу в каталог и далее переходит к карточке товара. В историю переходов попадают адреса всех этих страниц.

Если же пользователь переходит в приложение по прямой ссылке на карточку товара, то в историю переходов попадёт только адрес карточки. И если пользователь нажмёт на кнопку «Назад», он выйдет из приложения.

Такой выход может быть нежелательным. С помощью свойства `hierarchy` вы можете добавить в историю переходов дополнительные страницы, например каталог товаров и главную, тогда нажатии «Назад» пользователь останется в приложении.

Свойство `hierarchy` содержит массив объектов `RouteLeaf`, которые описывают пути для добавления в историю.

### Объявление объекта `RouteLeaf`

```TypeScript
export interface RouteLeaf {
  path: string;
  children?: RouteLeaf[];
}
```

| Свойство | Тип | Описание |
| --- | --- | --- |
| `path`&#x0d;&#x0a;*обязательное* | `string` | Путь в приложении. Может содержать [параметры](libraries/router/parameters), например `/catalog/:id`.&#x0d;&#x0a;&#x0d;&#x0a;**Важно.** Значения этого свойства должны соответствовать маршрутам, которые вы [определяете в своём приложении](libraries/router/setting-routes). |
| `children`&#x0d;&#x0a;*необязательное* | `RouteLeaf[]` | Список путей, которые следуют за текущим путём `path` в истории. |

### Пример использования

```TypeScript
import { AdaptivityProvider, AppRoot, ConfigProvider } from '@vkontakte/vkui';
import App from './App'; // Компонент вашего приложения
import { router } from './routes';
import { RouterProvider } from 'dist/index';

export const hierarchy: RouteLeaf[] = [{
  path: '/',
  children: [
    {
      path: `/catalog}`,
      children: [
        { path: `/catalog/:id`,
          children: [
            { path: `/catalog/:id/modal_page`}
          ]
        }
      ],
    }
  ],
}];

export const AppConfig = () => {
  return (
    <ConfigProvider>
      <AdaptivityProvider>
        <AppRoot>
          <RouterProvider router={router} hierarchy={hierarchy}>
            <App />
          </RouterProvider>
        </AppRoot>
      </AdaptivityProvider>
    </ConfigProvider>
  );
}
```

Дерево описывает возможные пути входа в приложение. Приложению можно передавать ссылки, которые соответствуют как концевым узлам дерева, так и средним.

Например, если передать такому приложению ссылку `/catalog/123/modal_page?inflate=true`, в историю переходов будут записаны следующие страницы:

* `/catalog/123/modal_page` (переданный путь)
* `/catalog/123` (предыдущий по отношению к переданному пути)
* `/catalog`
* `/` (самый ранний по отношению к переданному пути)

Если приложению передать ссылку из середины дерева, например `/catalog/123?inflate=true`, в историю переходов будут записаны следующие страницы:

* `/catalog/123` (переданный путь)
* `/catalog` (предыдущий по отношению к переданному пути)
* `/` (самый ранний по отношению к переданному пути)

### Замечания

Любой элемент дерева `hiearchy` — это маршрут, который может быть использован в прямых ссылках. Подумайте о возможных путях входа в ваше приложение, о дальнейших перемещениях с таких страниц и создайте элементы для каждой возможной прямой ссылки.

Если элемент дерева `hierarhy` встречается в нескольких ветках, приоритетной историей переходов будет считаться та, где этот элемент является оконечным узлом.
