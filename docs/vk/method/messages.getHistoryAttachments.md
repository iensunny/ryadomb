# messages.getHistoryAttachments

> Источник: [https://dev.vk.ru/ru/method/messages.getHistoryAttachments](https://dev.vk.ru/ru/method/messages.getHistoryAttachments)
Возвращает материалы диалога или беседы.

## Параметры

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| `attachment_types` | `string` | нет | Список типов материалов, который необходимо вернуть (comma-separated)<br>Доступные значения:<br>* `photo` — фотографии;<br>* `video` — видеозаписи;<br>* `audio` — аудиозаписи;<br>* `doc` — документы;<br>* `link` — ссылки;<br>* `market` — товары;<br>* `wall` — записи;<br>* `share` — ссылки, товары и записи.<br>Обратите внимание — существует ограничение по дате отправки вложений. Так, для получения доступны вложения типов `photo`, `video`, `audio`, `doc` , отправленные не ранее 25.03.2013, `link` — не ранее 20.05.13, `market,wall` — 01.02.2016. |
| `group_id` | `integer` | нет | Идентификатор сообщества (для сообщений сообщества с ключом доступа пользователя). |
| `peer_id` | `integer` | нет | Идентификатор назначения.<br> Для групповой беседы:<br>* `2000000000`+ `id` беседы.<br>Для пользователя:<br>* `id` пользователя. <br>Для сообщества:<br>* `-id` сообщества. |
| `cmid` | `positive` | нет | conversation message id (уникальный идентификатор сообщения в рамках беседы) |
| `attachment_position` | `positive` | нет | позиция аттачмента в сообщении (от 1 до NN) |
| `offset` | `string` | нет | смещение относительно cmid & attachment_position<br>- при отрицательном значении, будет возвращаться не более abs(offset) аттачей из будущего относительно cmid & attachment_position<br>- при значении >0, будет пропущено offset аттачей из прошлого относительно cmid & attachment_position<br>Можно передавать в диапазоне -200...200, при выходе за диапазон необходимо передать cmid и position последнего аттача и offset=1 |
| `count` | `positive` | нет | Количество объектов, которое необходимо получить (но не более **200**).<br>Рекомендованное значение - 100, так как некоторые виды аттачей на последнем этапе процессинга могут быть вырезаны по причине приватности и доступности |
| `extended` | `checkbox` | нет | Возвращать ли дополнительные поля для объектов [пользователя](reference/objects/user) и [сообщества](reference/objects/group) :<br>* `1` — возвращать.<br>* `0` — не возвращать, значение по умолчанию.<br>Дополнительные поля указываются в параметре `fields`.<br> |
| `fields` | `string` | нет | Дополнительные поля [профилей пользователей](reference/objects/user) и [сообществ](reference/objects/group), которые необходимо вернуть в ответе. |
| `max_forwards_level` | `positive` | нет | Максимальная глубина вложенности пересланных сообщений. |
| `message_video` | `checkbox` | нет | при значении 1 будет возвращать видео, которые не публичные, не интерактивные и не внешние (необходимо для сквозного просмотра) |
| `media_type` | `string` | нет | Тип материалов, который необходимо вернуть.<br>Доступные значения:<br>* `photo` — фотографии;<br>* `video` — видеозаписи;<br>* `audio` — аудиозаписи;<br>* `doc` — документы;<br>* `link` — ссылки;<br>* `market` — товары;<br>* `wall` — записи;<br>* `share` — ссылки, товары и записи.<br>Обратите внимание — существует ограничение по дате отправки вложений. Так, для получения доступны вложения типов `photo`, `video`, `audio`, `doc` , отправленные не ранее 25.03.2013, `link` — не ранее 20.05.13, `market,wall` — 01.02.2016. |
| `start_from` | `string` | нет | Смещение, необходимое для выборки определенного подмножества объектов. <br>Значение берется из поля `next_from`, которое возвращается на вызов `messages.getHistoryAttachments`. |
| `preserve_order` | `checkbox` | нет | Параметр, указывающий нужно ли возвращать вложения в оригинальном порядке. |
| `reverse_sort` | `checkbox` | нет | Сортирует аттачи в обратном порядке при = 1 |
| `photo_sizes` | `checkbox` | нет | Параметр, указывающий нужно ли возвращать доступные размеры фотографии в [специальном формате](reference/objects/photo-sizes). |

Если attachment_types не пустой, то используется новая логика метода (получение нескольких видов аттачей в прошлом и будущем в зависимости от offset и count)

## Результат

После успешного выполнения возвращает массив `items`, содержащий объекты, которые описывают вложения, а также дополнительное поле `next_from`, содержащее новое значение `start_from`. Каждый объект из массива `items` содержит следующие поля:

`message_id`
`integer`
Идентификатор сообщения, в котором было отправлено вложение.

`attachment`
`object`
Информация о вложении. 
Объект, который содержит следующие поля: 
* `type` (`string`) — тип вложения. Возможные значения:
    * `photo` — фотография;
    * `video` — видеозапись;
    * `audio` — аудиозапись;
    * `doc` — документ;
    * `link` — ссылка;
    * `market` — товар;
    * `wall` — запись.
* `photo`, `video`, `audio`, `doc`, `link`, `market`, `wall` (название поля зависит от значения поля `type`) — описание вложения. Содержит, соответственно, объект, описывающий [фотографию](reference/objects/photo), [видеозапись](reference/objects/video), [аудиозапись](reference/objects/audio), [документ](reference/objects/doc), [ссылку](reference/objects/link), [товар](reference/objects/market-item) или [запись на стене](reference/objects/post).
