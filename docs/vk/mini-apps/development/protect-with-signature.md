# Проверка подлинности данных

> Источник: [https://dev.vk.ru/ru/mini-apps/development/protect-with-signature](https://dev.vk.ru/ru/mini-apps/development/protect-with-signature)
Клиентская и серверная части мини-приложений обмениваются данными по интернету. Мошенники или недобросовестные пользователи могут пытаться подменить передаваемые данные, чтобы получить какую-либо выгоду.

## Использование подписи

При обработке критических или важных запросов важно удостовериться, что данные приходят из доверенных источников. Один из способов это сделать — сгенерировать специальную подпись для передаваемых данных в клиентской части и затем проверить эту подпись на сервере при получении запроса.

Такой подход является достаточно надёжным при условии, что подпись создаётся с помощью секретного ключа, неизвестного сторонним лицам. Платформа ВКонтакте использует подпись для [параметров запуска](mini-apps/development/launch-params-sign) мини-приложения, а также при работе с [платёжными уведомлениями](api/payments/notifications/vk).

## Как реализовать

Мы рекомендуем использовать защищённый ключ доступа из настроек мини-приложения (раздел [Разработка&nbsp;&rarr;Ключи доступа](mini-apps/settings/development/keys), значение **Защищённый ключ**). Он известен вам, то есть разработчику приложения, и неизвестен посторонним.

### Создайте подпись в клиентской части

Код клиентской части должен выполнить следующие действия:

1. Сформировать данные, которые должны быть подписаны. Если вам нужно передать несколько значений, вы можете составить пары `ключ=значение` и объединить их в строку.

1. Вычислить подпись для сформированной строки. Мы рекомендуем использовать для этого событие [`VKWebAppCreateHash`](bridge/VKWebAppCreateHash) библиотеки [VK Bridge](bridge/overview). 

    В общем случае вы можете применить любой способ, но использование события даёт следующие преимущества: 

    * Оно формирует подпись с использованием защищённого ключа доступа вашего мини-приложения и алгоритма [SHA256 с методом HMAС](https://ru.wikipedia.org/wiki/HMAC).

    * Использование события освобождает вас от необходимости включать криптографические библиотеки в клиентский код. 

    * Вам не нужно хранить ключ в коде как константу или передавать его по сети. Всё это снижает вероятность утечки ключа и повышает надёжность.

1. Отправить данные и подпись вашему серверу.

    > **Важно.** В результате вызова события `VKWebAppCreateHash` вы получаете сгенерированную подпись и значение времени, когда подпись была сформирована, в формате [Unix Timestamp](https://www.unixtimestamp.com/). И подпись, и значение времени надо передать серверу вместе с данными запроса.

#### Пример использования

```JavaScript

// Данные для отправки на сервер
let values = 'param1=value1;param2=value2';

bridge.send('VKWebAppCreateHash', {payload: values})
  .then((data) => { 
    if (data.sign) {
      // Подпись сгенерирована:
      // data.sign — подпись,
      // data.ts — время создания подписи 

      // Отправить подпись и время создания на сервер
      // https://example.com/?data=values&sign=data.sign&sign_ts=data.ts
    }
  })
  .catch((error) => {
    // Ошибка
    console.log(error);
  });
```

Если вы включаете .js-файл библиотеки VK Bridge в HTML-код своих страниц, то в JavaScript-коде надо использовать имя объекта `vkBridge`, а не `bridge`.

### Проверьте подпись на сервере

Ваш сервер получает запрос вместе с подписью. Он должен проверить подпись до выполнения действий, которые запрашивает клиентская часть.

Вычислить подпись на стороне сервера можно по [алгоритму, описанному ниже](#Алгоритм%20формирования%20подписи).
Событие `VKWebAppCreateHash` работает по такому же алгоритму.

Если вычисленная подпись совпадает с переданной, значит, запрос пришёл из достоверного источника и его можно выполнить.

## Алгоритм формирования подписи

1. Сформируйте список из следующих элементов:

    | Имя | Значение |
    | --- | --- |
    | `app_id` | Идентификатор вашего мини-приложения. Вы можете найти его в настройках мини-приложения в разделе [Настройки&nbsp;&rarr;&nbsp;Информация](mini-apps/settings/general/information). |
    | `request_id` | Данные, переданные в запросе, для которых надо вычислить подпись. Это те же данные, которые вы передавали событию `VKWebAppCreateHash` в параметре `payload`.&#x0d;&#x0a;&#x0d;&#x0a; **Обратите внимание:** событие `VKWebAppCreateHash` использует параметр с именем `payload`. При вычислении подписи на стороне сервера надо использовать имя `request_id`. |
    | `ts` | Время создания подписи в формате [Unix Timestamp](https://www.unixtimestamp.com/). Сервер получает это значение вместе с другими параметрами запроса. |
    | `user_id` | Идентификатор пользователя. |

1. Элементы в таблице выше представлены в алфавитном порядке. Этот порядок важен. Если вы добавляете элементы в список в другом порядке, отсортируйте список по названиям ключей до вычисления подписи.

1. Преобразуйте отсортированный список в строку. Используйте символ `&` как разделитель элементов.

1. Закодируйте строку с помощью алгоритма хеширования [SHA256 с методом HMAC](https://ru.wikipedia.org/wiki/HMAC). В качестве ключа используйте защищённый ключ из [настроек мини-приложения](mini-apps/settings/development/keys).

1. Преобразуйте полученные данные в [base64-строку](https://ru.wikipedia.org/wiki/Base64).

Подпись готова к использованию.

#### Пример

```PHP

// Значение защищённого ключа из настроек вашего приложения
$client_secret = "example-key-12345678"; 
// Подпись, полученная в запросе
$sign_param = 'fSibt9N1v3DYflFKFl2qyRk-g3szAKiGDL0p6fYGFSI'; 

$hash_params = [
  'ts' => 1630076629, // Время создания подписи
  'request_id' => 'abcdefgh', // Присваиваем значение параметра payload
];

// Добавляем идентификатор пользователя и мини-приложения или игры к ответу на событие
$hash_params['user_id'] = 1234;
$hash_params['app_id'] = 5678;

// Сортируем список по ключам
ksort($hash_params);

// Формируем строку для вычисления подписи
$sign_params_query = http_build_query($hash_params);

// Формируем подпись, используя защищёный ключ приложения (метод HMAC)\
$sign = rtrim(strtr(base64_encode(hash_hmac('sha256', $sign_params_query, $client_secret, true)), '+/', '-_'), '=');

// Сравниваем полученную строку со значением из VKWebAppCreateHash
$status = $sign === $sign_param;

echo ($status ? 'ok' : 'fail')."\n";
```
