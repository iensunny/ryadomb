# Обработка платёжных уведомлений ВКонтакте

Когда пользователь [покупает виртуальные ценности](api/payments/virtual-goods/vk) в игре или мини-приложении за голоса, ВКонтакте отсылает уведомления серверу этой игры или мини-приложения.

Уведомления — это POST-запросы в кодировке UTF-8. ВКонтакте отправляет их на [адрес обратного вызова](api/payments/virtual-goods/vk#Шаг%202.%20Укажите%20адрес%20обратного%20вызова%20в%20настройках%20приложения), указанный в настройках игры или мини-приложения.

Параметры уведомлений содержатся в теле POST-запроса в виде строки, содержащей пары `параметр=значение`, разделённые символом `&`. Ниже приведён пример уведомления вида `get_item`. ВКонтакте использует такие уведомления, чтобы получить информацию о товаре для отображения в окне покупки:

```
app_id=1524456&item=sale_item_1&lang=ru_RU&notification_type=get_item_test&order_id=2044594&receiver_id=1&user_id=1&version=5.132&sig=a71ec5b6c78940fa47a83796ee983ab6
```

Параметры уведомлений зависят от [типа уведомления](#Типы%20уведомлений). У каждого уведомления есть параметр `notification_type`, который сообщает серверу приложения тип уведомления.

## Типы уведомлений

| Тип уведомления | Описание |
| --- | --- |
| [`get_item`](api/payments/notifications/get-item) | Используется для получения информации о товаре для отображения в окне покупки. |
| [`order_status_change`](api/payments/notifications/order-status-change) | Информирует об оплате товара, а также об отмене оплаты и возврате товара. |
| [`get_subscription`](api/payments/notifications/get-subscription) | Используется для получения информации о подписке для отображения в окне покупки подписки. |
| [`subscription_status_change`](api/payments/notifications/subscription-status-change) | Используется при оплате, отмене и возобновлении подписки. |

Чтобы узнать о параметрах уведомлений и формате ответов, перейдите по ссылкам в таблице.

## Обработка уведомлений

Для сервера игры или мини-приложения уведомления — это входящие запросы. Сервер должны обработать уведомление, например предоставить пользователю купленный товар или преимущества подписки и вернуть результат об успешной обработке или ошибке.

:::note
Чтобы избежать повторных начислений товаров, реализуйте на сервере проверку по уникальному `order_id` и статусу заказа:

* Начисляйте товар по каждому `order_id` только один раз.
* Если получаете повторные уведомления, в которых статус заказа прежний, а по `order_id` уже начислен товар, возвращайте тот же успешный ответ, что и при первом начислении.
:::

#### Формат ответа

Формат ответа: JSON-данные в кодировке UTF-8. Структура JSON-ответа зависит от [типа уведомления](#Типы%20уведомлений).

#### Ответ необходим для проведения платежа

Сервер обязательно должен ответить на уведомление. ВКонтакте переводит голоса со счёта пользователя на счёт приложения только после получения ответа от сервера.

#### Максимальное время ответа

В случае отсутствия ответа на запрос ВКонтакте повторит его ещё несколько раз. Максимальное время ожидания ответа на запросы об информации о товаре — `get_item` и `get_subscription` — 60 секунд. Максимальное время ожидания ответа на другие запросы — 30 минут.

В случае получения ошибки ВКонтакте тоже может отправить запрос повторно: это зависит от значения поля `critical` в ответе. Если это поле сигнализирует о том, что ошибка временная, ВКонтакте повторит запрос спустя небольшой промежуток времени. [Подробнее](#Структура%20данных).

:::note
Повторные уведомления от ВКонтакте могут приходить с разных адресов. На каждое уведомление отвечайте статусом обработки заказа:

* Если товар уже начислен — верните успешный ответ, как при первом уведомлении.
* Если при обработке возникла ошибка — верните соответствующие код и текст ошибки.
:::

#### Проверка подписи параметров

Каждое уведомление ВКонтакте включает [подпись параметров](#Подпись%20параметров). Это значение, вычисленное по специальному алгоритму с использованием защищённого ключа из настроек приложения.

Сервер приложения должен проверять подпись параметров при обработке каждого уведомления. Это позволит вашему приложению защититься от мошеннических действий. Подробности — в разделе [Подпись параметров](#Подпись%20параметров).

#### Работа со строковыми данными

Строковые данные в уведомлениях закодированы в URL-кодировке, принятой в PHP. Например, пробелы будут представлены как `+`, символы национальных алфавитов и специальные символы — в записи через `%`, например, `%2F`.

Если ваш сервер был создан не на PHP, а на другом языке, вам нужно раскодировать эти значения перед обработкой уведомления. В частности, значения нужно раскодировать перед вычислением подписи параметров. [Пример в конце этого раздела](#На%20JavaScript) показывает, как можно раскодировать строки на JavaScript. Если вы используете другой язык, вам нужно создать функцию раскодировки самостоятельно.

#### Поддержка многоязычных интерфейсов

Обработчики уведомлений [`get_item`](api/payments/notifications/get-item) и [`get_subscription`](api/payments/notifications/get-subscription) возвращают информацию о покупаемом товаре или подписке.

В зависимости от языка пользователя (русский, английский и другие), эти обработчики могут возвращать различные данные для одного и того же товара или подписки.

Язык пользователя указан в параметре `lang`. Обработчики событий могут проверять значение этого параметра и возвращать название товара на языке пользователя. Это даёт возможность платёжным окнам выглядеть ожидаемо для клиентов в приложениях, поддерживающих многоязычные интерфейсы.

#### Кеширование информации о товарах и подписках

Вы можете разместить информацию о товаре и подписке, которую возвращают обработчики уведомлений [`get_item`](api/payments/notifications/get-item), в кеше на стороне платформы и использовать для более быстрой обработки последующих запросов.

Чтобы указать платформе, что информацию о товаре или подписке можно сохранить в кеш, сервер приложения должен в ответе передать параметр `expiration`, который указывает период хранения информации в кеше. Все запросы о товаре в течение этого времени будут обрабатываться ВКонтакте и не будут пересылаться серверу приложения.

Подробнее о параметре и его допустимых значениях можно узнать в описании уведомлений [`get_item`](api/payments/notifications/get-item) и [`get_subscription`](api/payments/notifications/get-subscription).

Мы рекомендуем использовать кеширование, насколько это возможно в вашем приложении. Это ускоряет обработку платёжных запросов и уменьшает нагрузку на сервер вашего приложения.

Данные для разных языков пользователя кешируются отдельно.

## Версия формата данных

ВКонтакте постоянно развивается, и формат данных и уведомления могут меняться со временем. Например, начиная с версии 5.132 становятся доступны уведомления об отмене платежа. Также, начиная с этой версии, ВКонтакте добавляет в уведомления параметр `version`, описывающий используемую версию.

Чтобы избежать ошибок, которые могут быть вызваны изменениями в формате данных, вы можете указать используемую версию уведомлений в настройках своего приложения, [в разделе Платежи](api/payments/virtual-goods/vk#Шаг%202.%20Укажите%20адрес%20обратного%20вызова%20в%20настройках%20приложения).

## Подпись параметров

С каждым уведомлением ВКонтакте передаёт параметр `sig`. Это подпись параметров — значение, вычисленное с помощью [защищённого ключа](mini-apps/settings/development/keys#Защищённый%20ключ) приложения. Ключ известен платформе ВКонтакте и авторам приложения, но неизвестен третьим лицам. Подпись в значительной мере затрудняет подмену параметров и защищает от мошеннических действий.

Серверная часть вашего приложения должна вычислять и проверять подпись параметров при обработке каждого уведомления.

Чтобы вычислить подпись:

1. Если вы используете не PHP-сервер, [раскодируйте строковые значения](#Работа%20со%20строковыми%20данными) из формата URL-кодировки, принятого в PHP.

2. Отсортируйте все пары `параметр=значение`, кроме параметра `sig`, в алфавитном порядке по имени параметра.

3. Соберите пары в одну строку. Не вставляйте разделители между ними.

4. Добавьте в конец строки значение защищённого ключа из [настроек вашего приложения](mini-apps/settings/development/keys#Защищённый%20ключ).

5. Для полученной строки вычислите хеш-код по алгоритму MD5.

Результирующее значение надо сравнить с полученным значением параметра `sig`. Если значения отличаются, запрос обрабатывать не надо, необходимо вернуть ошибку с [кодом `10`](#Коды%20ошибок) («Несовпадение вычисленной и переданной подписи»).

Примеры вычисления подписи приведены в разделе [Примеры обработчиков уведомлений](#Примеры%20обработчиков%20уведомлений).

## Формат ответа при ошибке

### Структура данных

Если при обработке уведомления произошла ошибка, необходимо отправить ответ в следующем формате:

```JSON
{
  "error": {
    "error_code": 1,
    "error_msg": "Описание ошибки",
    "critical": true
  }
}
```

| Поле | Тип | Описание |
|---|---|---|
| `error_code` | `integer` | [Код ошибки](#Коды%20ошибок). |
| `error_msg` | `string` | Описание ошибки в текстовом виде для чтения человеком. Это поле обязательно для ошибок, [определяемых самим мини-приложением или игрой](#Коды%20ошибок) (`error_code` больше или равен `100`). |
| `critical` | `boolean` | Критичность ошибки. Возможные значения:&#x0d;&#x0a; &nbsp;&nbsp; &bullet; `false` — ошибка носит временный характер, например, временная ошибка записи в базу данных. Такая ошибка говорит, что повторение запроса приведёт к успешному выполнению, поэтому ВКонтакте отправит повторно такое же уведомление через некоторое время. Приложение на стороне пользователя будет ожидать ответа на повторное уведомление.&#x0d;&#x0a; &nbsp;&nbsp; &bullet; `true` — ошибка носит постоянный характер, например ошибка вида «Указанного товара не существует». Такое значение поля `credential` говорит, что повторение уведомления с такими же параметрами приведёт к такой же ошибке. В этом случае ВКонтакте не будет отправлять уведомление повторно, а сразу вернёт ошибку. |

### Коды ошибок

| Код | Критичность | Описание |
|---|---|---|
| `1` | `true` или `false` | Общая ошибка. |
| `2` | `false` | Временная ошибка на стороне сервера, например ошибка базы данных. |
| `10` | `true` | Несовпадение вычисленной и переданной подписи параметров. |
| `11` | `true` | Одна из следующих причин:&#x0d;&#x0a; &nbsp;&nbsp; &bullet; Параметры запроса не соответствуют спецификации.&#x0d;&#x0a; &nbsp;&nbsp; &bullet; В запросе отсутствуют одно или более обязательных полей.&#x0d;&#x0a; &nbsp;&nbsp; &bullet; Ошибки целостности запроса. |
| `20` | `true` | Товара или подписки не существует. |
| `21` | `true` | Товара или подписки нет в наличии. |
| `22` | `true` | Пользователя, указанного в параметре запроса, не существует. |
| `100`...`999` | `true` или `false` | Ошибки с этими кодами задаются приложением.&#x0d;&#x0a;&#x0d;&#x0a;**Важно!** При использовании этих кодов возвращаемый объект обязательно должен содержать текстовое описание ошибки. |

## Примеры обработчиков уведомлений

### На PHP

```PHP
 <?php
header("Content-Type: application/json; encoding=utf-8");

$secret_key = 'abcdEFGHji12345'; // Защищённый ключ приложения
               

$input = $_POST;

// Проверка подписи
$sig = $input['sig'];
unset($input['sig']);
ksort($input);
$str = '';
foreach ($input as $k => $v) {
  $str .= $k.'='.$v;
}

if ($sig != md5($str.$secret_key)) {
  $response['error'] = array(
    'error_code' => 10,
    'error_msg' => 'Несовпадение вычисленной и переданной подписи запроса.',
    'critical' => true
  );
} else {
  // Подпись правильная
  switch ($input['notification_type']) {
    case 'get_item':
      // Получение информации о товаре
      $item = $input['item']; // наименование товара

      if ($item == 'item1') {
        $response['response'] = array(
          'item_id' => $item,
          'title' => '300 золотых монет',
          'photo_url' => 'http://somesite/images/coin.jpg',
          'price' => 5
        );
      } elseif ($item == 'item2') {
        $response['response'] = array(
          'item_id' => $item,
          'title' => '500 золотых монет',
          'photo_url' => 'http://somesite/images/coin.jpg',
          'price' => 10
        );
      } else {
        $response['error'] = array(
          'error_code' => 20,
          'error_msg' => 'Товара не существует.',
          'critical' => true
        );
      }
      break;

    case 'get_item_test':
      // Получение информации о товаре в тестовом режиме
      $item = $input['item'];
      if ($item == 'item1') {
        $response['response'] = array(
          'item_id' => $item,
          'title' => '300 золотых монет (тестовый режим)',
          'photo_url' => 'http://somesite/images/coin.jpg',
          'price' => 5
        );
      } elseif ($item == 'item2') {
        $response['response'] = array(
          'item_id' => $item,
          'title' => '500 золотых монет (тестовый режим)',
          'photo_url' => 'http://somesite/images/coin.jpg',
          'price' => 10
        );
      } else {
        $response['error'] = array(
          'error_code' => 20,
          'error_msg' => 'Товара не существует.',
          'critical' => true
        );
      }
      break;

    case 'order_status_change':
      // Изменение статуса заказа
      if ($input['status'] == 'chargeable') {
        $order_id = intval($input['order_id']);

        // Код проверки товара, включая его стоимость
        $app_order_id = 1; // Получающийся у вас идентификатор заказа.

        $response['response'] = array(
          'order_id' => $order_id,
          'app_order_id' => $app_order_id,
        );
      } else {
        $response['error'] = array(
          'error_code' => 100,
          'error_msg' => 'Передано непонятно что вместо chargeable.',
          'critical' => true
        );
      }
      break;

    case 'order_status_change_test':
      // Изменение статуса заказа в тестовом режиме
      if ($input['status'] == 'chargeable') {
        $order_id = intval($input['order_id']);

        $app_order_id = 1; // Тут фактического заказа может не быть — тестовый режим.

        $response['response'] = array(
          'order_id' => $order_id,
          'app_order_id' => $app_order_id,
        );
      } else {
        $response['error'] = array(
          'error_code' => 100,
          'error_msg' => 'Передано непонятно что вместо chargeable.',
          'critical' => true
        );
      }
      break;
  }
}

echo json_encode($response);
?>
```

// Вычисление подписи
function calcSignature(params) {

  const ACCESS_KEY = 'abcdEFGHji12345'; // Ключ доступа приложения

  // Сортируем параметры
  let keys = Object.keys(params);
  keys.sort();

  // Формируем строку из пар 'параметр=значение'
  let str = '';
  keys.map((item) => {
    if (item != "sig") {
      str += item + '=' + params[item];
    }
  });
  str = str + ACCESS_KEY; // Добавляем ключ доступа

  // Вычисляем подпись
  let calculatedSignature = md5(str);

  return calculatedSignature;
}

          app_order_id: appOrder 
      }};

      break;

    case 'refund': 
      // Обрабатываем возврат
      // ...
      break;
    default:
        responseData = { 
            error: {
                error_code: 11,
                error_msg: 'Ошибка в структуре данных',
                critical: true
            }};      
  }

}

// Служебная функция для декодирования строк
// из формата PHP URL-encoded
function PHPUrlDecode(str){
    return decodeURIComponent(
      str.replace(/%21/g, '!')
         .replace(/%27/g, '\'')
         .replace(/%28/g, '(')
         .replace(/%29/g, ')')
         .replace(/%2A/g, '*')
         .replace(/%7E/g, '~')
         .replace(/\+/g, '%20'));
}
